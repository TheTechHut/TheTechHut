PART TWO · THE RULES

Six formatting rules that travel well.

You do not need a different CV for every employer. Start with a simple, semantic document that can be read by both software and people.

RULE 01

One column. Always.

Two-column layouts can merge job titles, dates and skills when a parser reads across the page. Keep the document linear.

RULE 02

No tables, text boxes or icons.

Some systems drop table contents or ignore icons. Write labels such as Phone and Email as text.

RULE 03

Use familiar headings.

Use Work Experience, Education, Skills and Certifications instead of creative section titles.

RULE 04

Make dates consistent.

Use MM/YYYY, such as 03/2024 – Present, so systems can interpret your experience timeline.

RULE 05

Mirror the posting's nouns.

Use the exact technology and skill names in the job description, and show where you used them.

RULE 06

Keep PDF and Word copies.

PDF works well in many modern systems. Keep a .docx copy for employers whose forms request Word.

Languages: JavaScript (Node.js), Python, SQL

Data: PostgreSQL, Redis, MongoDB

WORK EXPERIENCE
Backend Engineer                         03/2024 – Present
Company Name, Nairobi, Kenya
- Reduced checkout failures by 31% by rebuilding the
  payment callback handler with idempotency and retries.

EDUCATION
BSc Computer Science                     09/2017 – 11/2021
University Name, Nairobi, Kenya

Tip: use the X-Y-Z pattern for bullets — what you did, the measurable result, and how you achieved it. Never invent numbers or experience you cannot defend.
